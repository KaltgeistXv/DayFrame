# DayFrame 需求文档（从当前项目反推）

日期：2026-09-14。代码基线：`8bcc3a0`。

本文件把当前实现整理为可维护的产品需求。标为“当前”的条目表示源码中存在对应能力，不表示每种设备、每个边界组合都经过人工验收。“建议”部分不算已经实现或本轮承诺。

## 1. 产品定位

DayFrame 是个人任务与项目工作台，帮助用户把零散事项归档、安排到日期、记录实际投入，并从不同视图了解进度。

核心用户：需要同时管理个人项目、日常事项和长期追踪任务的个人使用者。这里的定位依据现有项目和使用反馈反推，尚未经过正式用户研究。

核心价值：同一份任务数据贯穿收集、组织、排期、打卡与回顾，减少在多个页面重复录入和理解不同规则的成本。

## 2. 范围与页面职责（当前）

| 入口 | 用户目的 | 当前能力 |
| --- | --- | --- |
| 首页 | 快速了解需要关注的事项 | 统计与四个固定概览模块，提供后续入口 |
| 收集箱 | 整理没有日期的任务 | 未排期任务集合；代码允许列表、看板、日历、热力图 |
| 任务 | 集中管理所有任务 | 列表、看板、日历、甘特图、热力图及筛选 |
| 项目 | 查看项目和项目内任务 | 项目概览、项目排期和任务日历；单项目复用任务视图 |
| 标签 | 按主题查看关联任务 | 跨项目组织任务、统一标签管理 |
| 设置 | 管理工作空间与数据 | 名称保存、导出、导入、清空数据 |

设置界面已取消导航顺序调节和旧分栏。类型及兼容接口仍可能保留旧偏好字段，不能据此推断这些入口仍向用户开放。

未纳入当前产品承诺：多人协作、成员权限、付费订阅、外部日历双向同步、离线冲突合并。若以后要做，需要新增需求和相应架构验证。

## 3. 数据概念

| 实体 | 核心信息 | 关系 |
| --- | --- | --- |
| 任务 | 名称、状态、优先级、排期、备注、追踪属性 | 可属于一个项目，可关联多个标签 |
| 项目 | 名称、描述、颜色、排期方式 | 可属于一个文件夹，包含多项任务 |
| 文件夹 | 名称、排序 | 组织项目 |
| 标签 | 名称、颜色 | 为任务和项目提供分类 |
| 打卡记录 | 日期、进展备注、分钟数 | 属于任务，按日期记录 |
| 工作空间设置 | 名称及兼容偏好 | 工作空间级别 |

临时的拖动预览、日历顺延投影、正在编辑的草稿不作为独立任务持久化。主要字段见 `lib/model.ts`；数据库表示见 `db/schema.ts`。

## 4. 业务规则（当前）

- 任务状态为待开始、进行中、已完成；优先级为高、中、低。
- 未排期表示没有日期；全天表示有日期但没有具体时刻。
- 全天范围包含结束日期；定时任务以开始时刻和分钟数表示范围。
- 原计划来自用户排期；追踪任务的自动顺延是进度投影，不自动生成实际打卡记录。
- 打卡表示投入，不自动等价于完成；完成日与历史记录需保持一致。
- 不允许记录未来日期；已完成任务的可记录范围受完成日约束。重新排期不能抹去历史记录。
- 项目支持跟随任务与手动排期；项目汇总与任务明细表达不同层级。
- 项目/标签共用六色；旧值进入统一映射，不维持另一套新建颜色规则。
- 删除项目后任务保留并解除项目关联；取消排期清除日期和时间，不删除任务。
- 撤销/重做由工作空间历史管理；恢复快照会检查当前数据，避免静默覆盖其他修改。不要承诺刷新后仍保留会话撤销栈。

## 5. 主要链路与验收条件

| 编号 | 场景 | 预期与验收 |
| --- | --- | --- |
| R01 | 快速收集 | 从新建任务入口创建无日期任务；收集箱可见，刷新后仍存在 |
| R02 | 编辑任务 | 可改名称、归属、状态、优先级、标签、日期和备注；成功后各视图同步；失败保留可重试草稿 |
| R03 | 组织项目 | 新建项目可选文件夹与六色，选标签；项目详情与概览反映同一数据 |
| R04 | 切换视图 | 列表、看板、日历、甘特共用任务；视图切换保留既定上下文，不悄悄改变业务归属 |
| R05 | 日历排期 | 年/月/周/日围绕日期浏览；跨天任务连续表达；拖动、拉伸和日期编辑遵循共同排期计算 |
| R06 | 甘特浏览 | 项目分组与任务明细有层级，折叠后日期列与任务行仍对应，今日标识连续且清楚 |
| R07 | 打卡 | 有追踪或记录的任务可进入打卡页；点击日期编辑当日进展，未来日期不可保存 |
| R08 | 草稿与打卡共存 | 修改任务草稿后切换到打卡，保存打卡不覆盖未提交的标题和排期 |
| R09 | 首页进入任务 | 从摘要进入相应任务范围；明确的入口意图优先于旧视图记忆 |
| R10 | 设置改名 | 修改名称后保存，显示成功反馈，工作空间名称更新，刷新后保留 |
| R11 | 数据导出/导入 | 支持 DayFrame JSON 备份，导入前验证格式并显示数量；最大 10 MB；区分合并与替换，替换有确认 |
| R12 | 清空数据 | 展示影响和确认；备份取消或保存流程未完成时不能谎报备份成功；清空后回到默认状态 |
| R13 | 操作恢复 | 支持已有范围内的撤销/重做；编辑框自己的撤销不被全局快捷键抢占 |

这些是可执行的回归场景。新增功能时给新场景编号；不要仅用“优化一下”作为验收条件。

## 6. 体验要求

- 同功能同名、同层级同规则；文案简洁但保留必要含义。
- 字体使用系统字体；按钮、表单、菜单、页签和浮层复用公共规范。
- 弹窗在内容较多时仍能定位操作区，窄屏合理换行与滚动。
- 拖动有来源、目标和预览反馈；无效目标、取消及保存失败需有明确行为。
- 保存中阻止重复提交；错误可被看见，成功反馈应与实际保存结果一致。
- 已完成、未排期、无结果、首次使用等状态都有合理展示。
- 支持键盘焦点、必要的无障碍名称和减少动效偏好。

具体尺寸、视觉值与交互细则引用 `docs/ui-system.md` 和 `docs/spacing-system.md`，本需求文档不再维护第二套参数。
