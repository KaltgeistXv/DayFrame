# DayFrame 界面规范

## 唯一入口

- `app/ui-tokens.css`：尺寸、字体、字重、行高、阴影、动效、状态色与 z-index。
- `components/ui/`：复用组件和样式。相同功能层级不按页面单独定尺寸。
- `app/globals.css`：视图布局、数据几何及兼容旧结构的适配规则。

## 尺寸与布局

| 层级 | 规范 |
| --- | --- |
| 页面 | 外侧 32px，小屏 16px |
| 主面板 | 内侧 24px，小屏 16px；圆角 22px |
| 内部卡片 | 内侧 16px；圆角 16px |
| 模块 | 间距 24px，小屏 16px |
| 任务行 | 最小高度 56px，内侧和内容间距 12px |
| 表单 | 字段间距 16px，标签与控件间距 8px |
| 标准控件 | 高度 36px；文字按钮左右 16px，小按钮 12px；图文间距 8px |
| 工具栏 | 最小高度 40px，内容间距 8px；下方留白由外层统一负责 |
| 紧凑控件 | 28px / 32px，用于行内或辅助操作 |
| 大控件 | 40px；触摸目标参考 44px |
| 圆角 | 小部件 6/8/10px，卡片 16px，面板 22px，按钮 10px，分段选中项与圆点使用全圆角 |

控件用 min-height 支持文字换行；同层级共享内边距，禁止父子同时添加相同外部留白。窄屏优先换行，数据网格允许内部横向滚动。日历刻度、甘特列宽、预览坐标属于数据几何，单独维护。

## 字体、图标与文案

字体统一使用系统字体：`--ui-font-sans` 优先 `system-ui`，由操作系统选择本机界面字体，中文按系统字体回退。等宽内容通过 `--ui-font-mono` 使用本机等宽字体。页面、弹窗、菜单、控件与拖动预览共享这些入口，不引入或下载网页字体。`font` 简写同样必须引用公共字体变量，不能绕过 `font-family` 规则。

| 用途 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | 24px | 600 | 1.35 |
| 弹窗标题 | 18px | 600 | 1.35 |
| 分区标题 | 16px | 600 | 1.35 |
| 任务标题、按钮、字段名称 | 14px | 500 | 1.5 |
| 正文 | 14px | 400 | 1.5 |
| 次要信息 | 13px | 400 | 1.5 |
| 辅助信息 | 12px | 400 | 1.5 |
| 密集图表微标注 | 11px | 400 | 1.5 |
| 统计数字 | 28px | 600 | 紧凑行高 |

11px 仅用于图表辅助标注，不能作为主要任务或按钮文字。品牌字标允许专用字重；日期和计数使用等宽数字。使用 `--ui-text-*`、`--ui-weight-*`、`--ui-line-*`；Tailwind normal/medium/semibold 同步到此入口。

## 配色规则

主题值集中在 `app/ui-tokens.css`，浅色和深色使用相同语义名称。主界面保留现有配色：黑色侧栏、浅灰画布、白色内容面板。只在主题入口定义基础色，组件引用用途变量。

| 用途 | 变量 | 使用原则 |
| --- | --- | --- |
| 画布、面板、浮层 | `--df-canvas`、`--card`、`--popover` | 通过表面区分结构 |
| 主文字、次要文字 | `--foreground`、`--muted-foreground` | 标题/正文与说明/日期两级，不随机选灰 |
| 主操作 | `--primary`、`--primary-foreground` | 主要按钮，避免大量竞争 |
| 控件边框、分隔线、焦点 | `--input`、`--ui-border-divider`、`--ring` | 用途独立，不相互替代 |
| 成功、提醒、危险、信息 | `--ui-color-success/warning/danger/info` | 保留文字或图标，不只靠颜色传达状态 |
| 悬停、按下 | `--interaction-hover/pressed` | 复用现有浅底反馈 |
| 项目身份 | `lib/colors.ts` 的 palette/colorStyle | 保留用户项目颜色，浅底搭配深色文字；不得用状态色覆盖 |

禁用态沿用公共组件透明度，不新增灰色；选中沿用公共状态规则。`ui-type-*` 和 `ui-tone-*` 可用于新的同级组件，已有组件通过集中适配接入。历史业务图表色与品牌样式不批量抹除，后续修改时按语义迁移。

图标使用 Lucide：标准 16px，紧凑 12–14px；圆点等宽等高且不收缩。图标按钮提供 aria-label；图标不替代必要的状态文字。

标题直接命名，按钮使用动作词。已有数字或状态不再补重复说明。空状态只说明当前状态并提供一个相关操作；错误说明问题与重试入口。

## 组件复用

| 功能 | 共用实现 |
| --- | --- |
| 日期前后切换 | `DateStepControls`：日历、甘特图、热力图共享按钮；各视图只传入步长和禁用条件 |
| 视图工具栏 | `ViewToolbar`：列表、看板、日历、甘特图、热力图及项目视图 |
| 任务与项目行 | `ui-interactive-row`：首页、列表、未排期任务 |
| 按钮 | `Button` 的 variant / size；图标按钮用 icon 尺寸 |
| 输入框与多行输入 | `fieldControlClass` + Input / Textarea |
| 选择器、下拉与右键菜单项 | `menuItemClass`，共同定义高度、圆角、图标间距和禁用状态 |
| 浮层 | `overlaySurfaceClass`，统一边框与阴影 |
| 状态与项目标签 | Badge / ProjectBadge，颜色表达业务身份 |
| 空状态 | Empty 系列组件 |

视图只提供内容、事件和必要的数据布局，不复制基础样式。扩展优先新增有意义的 variant，避免按某个页面名称增加例外。

## 状态、层级与动效

结构面板无悬停抬升；可点击卡片使用共享微阴影。行内交互使用浅底色，选中用细描边，键盘焦点用可见轮廓。父行和子按钮不叠加阴影。禁用不暗示可操作，错误与危险操作保留语义色。

悬停 140ms、普通反馈 180ms、弹窗进入 200ms、菜单 160ms。只过渡所需属性，不使用 transition: all，不靠位移改变点击区域。拖动期间位置直接跟手；落点每帧最多计算一次，结束或取消清理预览。尊重系统减少动态效果设置。

阴影使用 `ui-shadow-*`；层级使用 `layer-*`，不能为单一页面随意提高 z-index。菜单、提示和弹窗使用现有浮层组件维护焦点、Escape 和键盘导航。

## 维护与验证

新增组件先检索同功能组件；尺寸与色彩优先引用 token。禁止复制整段 CSS 只改页面选择器。旧布局适配保留必要的选择器优先级和媒体条件；修改时编辑已有规则，不在文件末尾追加同选择器覆盖。相同条件下的重复声明由检查脚本阻止。

调整基础规范后运行类型检查、构建和相关行为测试。拖拽、缩放、撤销等交互不得仅靠 CSS 外观检查。需要视觉确认时对照同一宽度与同一内容状态，不用空状态与满数据视图相互比较。

日程与热力图明细复用 `ui-interactive-row--compact`：44px 最小行高、8px/12px 内边距，标题与项目允许同行换行；交互反馈继承公共任务行，不增加独立阴影或嵌套边框。

日/周排期布局：辅助月历栏共用 `--layout-schedule-rail`（224px），主时间轴占剩余宽度；辅助栏采用紧凑任务行、14px 标题与24px 日期标记，保留既有窄屏布局。

年视图缩放优先改变留白，不缩放字号与24px 日期标记。桌面4×3布局按可用高度分配30–44px日期行、16–32px月份行距；到达可读下限后滚动，避免强制压进一屏。此为参考截图提炼的布局策略，并非苹果内部实现。

弹窗滚动条：统一细轨道、透明背景和圆头滑块，颜色由 `--ui-scrollbar-*` 控制。内部正文预留稳定滚动槽与8px内容间隔；现有单一正文滚动容器负责滚动，标题和底部操作保持原布局。不使用滚动平滑动画干预用户输入。


## 规则如何互通

依赖方向固定为：主题/基础 token → 语义规则 → 公共组件 → 视图内容。视图只能选择公共角色、尺寸或 variant；公共组件不能反向依赖某个页面的名字。修改共享 token 后，所有消费者同步更新。

| 规则 | 唯一入口 | 消费者 |
| --- | --- | --- |
| 主题、尺寸、排版、语义色 | `app/ui-tokens.css` | CSS、Tailwind theme、公共组件 |
| 字体/字重 | `ui-font-*`、`ui-text-*`、`ui-weight-*` | 主界面、门户弹窗、菜单与表单 |
| 菜单项/子菜单触发器 | `menuItemClass`、`menuSubTriggerClass` | Select、ContextMenu、DropdownMenu |
| 浮层外观 | `overlaySurfaceClass`、`dialogSurfaceClass` | 菜单、选择器、Popover、Dialog、AlertDialog |
| 浮层动效 | `motion-style.ts` → `--motion-*` | 公共浮层组件；减少动态效果时停用 |
| 表单控件 | `fieldControlClass` | Input、Textarea；错误、焦点、禁用共用 |
| 滚动 | `--ui-scrollbar-*` 与弹窗正文规则 | 各编辑弹窗、内部文字输入 |
| 工具栏与日期导航 | `ViewToolbar`、`DateStepControls` | 所有任务视图 |
| 任务行 | `ui-interactive-row` / compact | 首页、列表、日程、热力图明细、未排期 |
| 拖拽 | `drag-feedback`、`DragActionDock` | 拖动预览、落点、未排期/删除入口 |
| 滚动吸附 | `bindCalendarSnap`、`animateCalendarSnap` | 月历纵向与日/周横向；惯性结束后只吸附一次 |
| 项目身份色 | `lib/colors.ts` | 标签、日历条、甘特条和项目圆点 |

### 状态契约

- 默认：内容可读，结构面板不提示可点击。
- 悬停：任务行浅底，菜单当前项浅底；圆形日期仅圆形区域触发视觉反馈。
- 按下：共享 pressed 色，不位移布局。选中与 hover 分开，不能用悬停影代替选中状态。
- 键盘焦点：可见 focus-visible；菜单保留组件库方向键、Escape、边界定位与焦点恢复。
- 禁用：保留语义和标签，公共组件处理交互阻止及透明度。
- 危险操作：语义红、独立分组，沿用已有确认，不因视觉重构改变业务行为。
- 加载/空/错误：沿用当前业务状态与操作入口，不用隐藏数据制造整齐。
- 触摸与窄屏：换行/滚动优先；不得为了单屏压缩主要文字或裁掉操作。

### 与业务规则的边界

不把日历日期运算、甘特拖动坐标、历史完成状态、打卡与撤销放进视觉 token。它们保持在现有业务模块，由视图传数据给公共组件。自定义项目颜色和图表几何是明确例外，不做批量替换。旧的 `--ui-body`、`--ui-control` 等别名已迁移，不再新建同义变量。

### 自动检查

运行 `node scripts/check-ui-system.mjs`，检查所有 app/components/hooks/lib 源文件中的自有 token 是否有定义、浅深主题是否出现循环、旧变量是否回流，以及公共浮层是否重新硬编码时长。外部字体和组件库定位变量保留由对应库提供。

运行 `node --test tests/ui-system.test.mjs` 验证检查器本身；行为测试和构建独立运行。此检查不替代视觉对照，也不把尚未迁移的历史图表几何误报为错误。当前 `globals.css` 仍包含历史布局适配，修改对应功能时逐步替换，不以一次重写全文件承担回归风险。


## 跨视图同步约定

同一功能、同一层级默认完全复用，页面不覆盖字体、圆角、边距、反馈色。差异通过公共 variant（例如标准/紧凑任务行）表达；改 variant 的 token 会同步所有使用它的视图。月/年与日/周的未排期行共同使用 compact，菜单组件与历史适配共同读取 `--ui-menu-row-*`。需要新差异时，先确认是数据几何、响应式布局还是复用 variant，避免新增页面专属外观。


## 产品文案

跨视图重复文案统一引用 `lib/ui-copy.ts`，仅用于界面，不参与存储字段或用户输入。新增文案先按上下文选择：

- 操作：动词开头，明确对象；独立入口“新建任务/新建项目”，有标题的表单用“保存/创建/取消”。
- 状态：“待开始/进行中/已完成”；排期状态统一“未排期”，追踪分类统一“追踪任务”。不混用待安排、持续追踪等同义词。
- 空状态：无数据用“暂无任务”，筛选无结果用“未找到任务”；需要帮助时提供操作，不堆叠重复说明。
- 处理中：“保存中…/删除中…/加载中…”；只有真实完成才写“已保存”，下载已发起不能写成文件已保存。
- 提示：影响结果的信息必须保留；低频拖动指导可放工具提示。无障碍名称保留任务对象和状态，不能为字数省略。
- 同层级追求语义、语气与长度接近，不为凑字数增加“进行/操作”等虚词。
- 危险操作保留影响范围、可撤销性和确认；不简化为含义不明的“确定”。


### 跨入口名称一致

字段、选项、菜单、拖拽浮层和提示中的同一功能统一引用 `lib/ui-copy.ts`，不在各视图重复定义。弹窗已有对象标题，字段统一为“名称、颜色、状态”；归属字段保留“所属项目、所属文件夹”，明确对象层级。排期方式统一为“跟随任务、手动排期”。清除日期和时间统一叫“取消排期”，不使用“移回收集箱”描述这项操作；拖动提示为“松开取消排期”，补充说明为“清除日期和时间”。新建/编辑弹窗的提交按钮统一为“创建/保存”。删除动作名称统一，确认发生在实际操作流程中，不靠菜单名称省略号表达。无障碍描述、错误信息可保留完整上下文。

`check-ui-system.mjs` 检查组件中已废弃的同义名称，阻止它们重新分散到不同入口；不会检查或改写用户数据。

## 导航与默认状态

统一入口意图由 `lib/navigation-policy.ts` 定义。主页数字入口必须到达其数字代表的任务集合：今日待办→今天未完成任务，未排期→收集箱未完成任务，延期任务→延期且未完成的追踪任务，今日打卡→今天有打卡记录的全部任务（包括已完成任务）。结果使用可见、可清除的“任务范围”筛选，并在切换任务视图时保持一致。“今日安排”的查看全部直接打开今天日历；普通项目入口使用该项目记住的视图。

状态规则：首次访问各分组展开；用户的手动折叠在当前会话按栏目保存，列表与看板共享，项目之间互不影响。明确统计/安排入口展开目标栏目的状态分组；普通导航不重置折叠。重复点击当前栏目保留筛选、视图和阅读位置。切换视图保留日期和筛选，只有明确“今天/今日安排”操作回到今天。换栏目清除旧栏目筛选，避免内容意外被隐藏；筛选面板默认收起，活动条件始终可见。

任务创建继承当前项目或项目筛选、标签或标签筛选、优先级、追踪条件与当前日期上下文。新建或更改状态后展开目标状态分组；修改名称、备注等信息后保存关闭弹窗，保留原阅读位置。只有新建或调整排期才定位日历日期。任务名称进入任务详情，打卡入口进入打卡记录，项目名称进入项目任务，删除保留统一确认流程。不得用同一入口名称指向不同范围，不得为降低操作次数跳过删除确认。


## 拖拽反馈

原位置统一淡化并保留布局。原生拖拽使用 `lib/drag-feedback.ts` 的精简预览：仅标题与项目，不复制页面内容，不放无功能的勾选圆圈；位图按设备像素比绘制，采用当前主题字体、文字、背景和描边。柔和阴影只用于浮起预览，目标位置不投影。

目标类型必须与实际操作一致：手动排序标记 `data-drop-kind="insert"`，在目标前显示插入线；自动排序卡片使用 `status-child`，提示移入其 `status` 列，不承诺任意排序位置。日历和甘特图使用实际排期计算结果绘制范围，继续共用 `feedback-ring` 和 `feedback-fill`。未接受的落点不高亮；取消排期、删除使用统一操作浮层。拖动几何不加缓动，dragover 每帧合并一次；松开、取消、失焦与卸载清除全部反馈及待执行帧。

### 紧凑编辑表单

编辑弹窗通过 `DialogContent.editorLayout` 接入共同布局：`form`（任务/项目）、`activity`（打卡）、`settings` 共用 680px 内容宽度，`compact`（文件夹/标签/批量改期）为 440px，均受视口安全区约束。字段采用上标签、下控件；名称/归属/备注占整行，状态与优先级、开始与结束成对排列，小屏自然单列。分组间距、字段间距、控件、字体、底部操作均使用全局 token，不为各个弹窗重新定义。打卡在任务详情和独立入口共用同一组件：日历与进展并排，历史记录横向铺满底部，窄窗口单列；历史记录保留有界滚动，避免记录增多时挤掉输入区。设置沿用相同字段与分组规则，名称与数据操作在同一页按内容分组。标题和提交区由公共弹窗框架保留。

弹窗内部用间距分组：属性分组、备注区、打卡记录和底部操作区不绘制装饰分隔线或嵌套边框。任务详情使用全局填充分段切换栏；设置直接单页展示，不再设置页签。分段控件规范为：浅灰底、深色选中项、无下划线，字号/高度/圆角/反馈沿用全局 token。旧表单、页脚和记录容器不再单独定义装饰边线，避免样式优先级使分隔线重新出现。输入控件边界、焦点轮廓和弹窗外框保留，保证可操作性与层次。

甘特图的项目层级只组织左侧任务树，不用整行底色或粗横线切断时间轴。分组标题行与任务行使用相同日期列，今天指示连续穿过分组；左侧项目名称紧凑显示，子任务缩进。任务甘特图与项目甘特图共用 GanttGroupHeader。

甘特图默认以排期为主：每项任务一行，不显示逐日打卡圆点和打卡深浅切片，只保留原计划与顺延区段。工具栏“显示打卡明细”恢复逐日记录，任务甘特和项目甘特共享当前会话的开关状态。切换仅影响显示，不修改任务、打卡或排期数据。日期采用紧凑单行刻度，横线弱化，竖向日期网格保持连续。

### 甘特图接入边界

甘特页面复用 ViewToolbar、DateStepControls、公共图标按钮和 uiCopy；字体、字重、辅助色、焦点、图标、圆角与动效均通过全局变量。任务视图和项目视图共享 GanttHeader、GanttGroupHeader、TaskTimelineRow 与打卡明细偏好。日期列宽和左侧冻结列、拖动命中与排期范围计算属于几何逻辑，保留为专用定义，不以通用控件尺寸替换。样式修改优先更新现有规则，清理失效的项目汇总行与表头覆盖。

弹窗与内部选择器的动作规则：普通文字按钮左右留白 16px、小按钮 12px；提交/取消动作最小宽度 72px、最小高度 36px、按钮间距 12px，图标按钮保持正方形。页脚、打卡操作和内联创建共同复用该规则；窄屏允许换行。文件夹/标签编辑正文使用网格承载字段间距。选择器中的“新建”统一为左对齐加号菜单行，不添加分隔线或常驻色块；内联创建使用整行输入、下一行取消/创建，并引用统一文案。项目与标签选择器宽度上限由 ui-picker-width 控制；弹窗和菜单阴影由全局 ui-shadow-modal/popover 同步，禁止局部叠加。

颜色只由 lib/colors.ts 的六色 palette 定义：雾蓝、浅紫、森林绿、石墨灰、莓红、杏橙。详情使用直达色圈，项目/标签右键菜单显示同一组色圈，不使用二级菜单。两种入口共享尺寸、选中与键盘焦点样式；详情随表单保存，右键即时保存并通过工作空间数据同步到所有视图。已有旧预设按颜色家族归并，自定义颜色按最近标准色归并；详情选中状态、全局渲染、保存和备份导入统一经过 normalizeColor，旧色值不再写入。迁移只更新项目与标签的颜色，不修改任务和打卡数据。

### 创建与编辑状态

所有项目创建入口共用 `createProjectDraft` 和 `ProjectEditor`。草稿可预分配 ID，用于从任务内新建后关联；是否已保存必须查询工作空间中的项目集合，不能用 ID 是否为空判断。创建显示“新建项目 / 创建 / 创建中…”，只有已保存项目显示“编辑项目 / 保存 / 保存中…”及删除入口。保存成功才关联任务并关闭；失败保留内容与错误；取消、关闭和成功保存均清除关联意图，下次打开重新判断。项目表单局部错误不污染任务表单。

抽屉位于侧栏之上、模态弹窗之下，分别使用 `layer-sheet-backdrop/sheet`；弹窗、菜单、提示仍使用对应的既有层级。抽屉的滑入方向属于组件行为，时长、阴影和字体必须消费全局变量。减少动态效果与关闭动效对所有浮层生效。

检查覆盖：活跃组件的动效、阴影、层级硬编码，词典已有文案的重复定义，废弃日历选择器，无入口引用的业务组件，以及同选择器、同父级、同优先级下被末次声明覆盖的完全相同声明。不同值的兼容回退、不同媒体条件和数据几何不自动删除；未使用的基础组件库不作为废弃业务组件处理。组件提取后仍应测试入口、保存失败、取消与跨入口状态。

设置采用单页结构：名称、导出、导入、清空共用 `dialog-action-section` 的标题/说明与右侧操作布局，小屏操作自然换行。名称保存显式提交，只更新名称并保留其余偏好，成功后显示反馈且保持设置打开。导航排序入口与拖动/上下移动控件移除，已有排序数据继续兼容。文件选择使用中文公共按钮触发隐藏的原生文件输入，验证通过后才展示导入预览；清空确认按需展开，复用公共复选框和操作按钮，保留备份与明确确认。

设置与其他编辑弹窗共用外框、标题、系统字体、响应式内边距、按钮尺寸和状态反馈。正文使用 `DialogBody`，与项目、文件夹和标签编辑共用滚动边界、滚动槽和焦点留白；设置不再覆盖外框尺寸或为窄屏单独设置内边距。设置名称字段沿用表单标签的次级字号和字重，保存为主要操作，导出和选文件为次要操作。操作行按钮与公共页脚消费同一尺寸规则，预览及确认区共享间距和表面，保留其必要业务结构。


维护样式时直接修改当前规则，不追加同选择器覆盖。校验脚本检测同一条件下已被后续声明完整取代的旧值（包含等权重的 :is 选择器）；逗号选择器必须每个分支都已被覆盖。媒体条件、层、状态和同一规则中的兼容回退保留。清理同时核对动态类名与实际入口，弹窗原生字段旧皮肤及通用 editor 尺寸已移除，外框和字段只通过 editorLayout 与公共控件接入。


### 自动执行

根目录 AGENTS.md 是后续代码修改的规范入口。npm dev/lint/build 的前置生命周期自动运行 check:ui，失败时退出；开发服务器监听 app/components/hooks/lib 中源文件的增删改并自动提示 UI 规则错误，修正后提示通过。npm run check 汇总 UI 规则、lint、类型检查与测试。可机械判断的约束由脚本拦截；视觉层级、业务合理性和拖动几何仍需要按修改范围进行实际页面检查。直接运行底层 CLI 可绕过 npm 前置钩子，因此交付流程统一使用 npm 脚本。


## 业务模块职责

- `components/workspace.tsx` 负责视图组合、筛选、导航意图和编辑入口；不直接实现持久化请求或撤销栈。
- `hooks/use-workspace-data.ts` 负责加载、保存锁、请求顺序、快照更新与撤销/重做。`lib/workspace-client.ts` 统一请求与响应错误，API 元信息不进入工作空间快照。
- `components/task-editor.tsx` 负责任务表单和打卡页展示，保存与导航由工作空间协调。修改打卡记录必须保留尚未保存的标题和排期。
- `lib/task-editor.ts` 负责结束日期/时间的共同校验；两个输入保持一致的时长上限，全天范围包含结束日期。
- `components/planner.tsx` 负责排期页面和原生拖放入口；`hooks/use-planner-gesture.ts` 负责指针手势、框选、预览、捕获与边缘滚动。坐标计算保留排期专用规则。

新功能先归入对应职责；只有产生新的独立职责才新增模块，避免按每个按钮拆文件。提取组件保留公共样式与 DOM 约定，不建立平行的样式系统。
